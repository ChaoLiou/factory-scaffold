# 產品合約

這份文件定義產品合約。名詞一律照 `../CONTEXT.md`。

技術棧還沒定。這份合約的用途是讓技術棧可以晚點定：任何技術棧只要滿足合約，工廠就接得上。

---

## 1. 為什麼先定合約

驗證站要用一份技能檔服務所有工廠。一份要處理三種技術棧的技能檔，改善速度是三分之一。

但「固定一套技術棧」不是目的。目的是那一份技能檔有固定的東西可以依賴。

所以先定「技能檔依賴什麼」，再選「哪一套技術棧最便宜地提供它」。順序反過來會把選擇綁死在一個還沒驗證過的判斷上。

合約有三項要求。三項都是驗證站要的。

---

## 2. 要求一：每個 PR 一個預覽網址

### 內容

| | 條件 |
|---|---|
| 必須 | 每個 PR 自動產生一個 HTTPS 網址 |
| 必須 | PR 推新 commit 之後，網址指向新版本 |
| 必須 | 網址的壽命至少七天 |
| 必須 | 網址不需要登入就打得開 |

### 理由

沒有預覽網址，證據產生器無從操作產品。

七天這個數字來自關卡：廠主可能隔幾天才看證據。網址在他看之前就失效，證據等於沒有。

### 怎麼檢查

工廠在 PR 上讀得到一個預覽網址，並且那個網址回 HTTP 200。

---

## 3. 要求二：一組可重現的初始資料

### 內容

| | 條件 |
|---|---|
| 必須 | 一個指令就能把產品回到已知狀態 |
| 必須 | 同一個 commit 跑兩次，證據的畫面一致 |
| 必須 | 每個預覽網址有自己的資料，不與其他預覽網址共用 |
| 必須 | 初始資料存在版本控制裡 |

### 理由

這一項最難，所以它決定技術棧的選擇。

沒有可重現的初始資料，每次錄影的畫面都不一樣。廠主看兩段影片，分不出差別是這次改動造成的，還是資料不同造成的。那證據就不是證據。

「不與其他預覽網址共用」是因為兩個 PR 會同時在跑。共用一個資料庫，兩邊的證據互相污染。

### 怎麼檢查

連跑兩次證據產生器，截圖逐像素比對。

畫面上本來就會變的區域（時間、動畫、隨機排序）列進容許清單。容許清單要寫在工廠的設定裡，不是寫在技能檔裡 — 每個產品的動態區域不一樣。

---

## 4. 要求三：一個固定的登入方式

### 內容

| | 條件 |
|---|---|
| 必須 | 一組測試帳號，由初始資料建立 |
| 必須 | 登入步驟固定，而且不需要人 |
| 必須 | 產品有角色之分時，每個角色一組帳號 |
| 禁止 | 簡訊驗證碼 |
| 禁止 | captcha |
| 禁止 | 跳轉到第三方的 OAuth |

### 理由

民眾的產品幾乎都有登入。沒有測試帳號，證據產生器只錄得到首頁。

三條禁止項都是同一個原因：它們需要人介入，而驗證站上面沒有人。

產品自己可以有簡訊驗證或 Google 登入。合約要求的是**另外**有一條給 agent 走的固定路徑。

### 怎麼檢查

證據產生器用技能檔裡寫死的步驟登入，然後抓到一個只有登入後才看得到的畫面。

---

## 5. 合約不管的事

合約刻意不限制這些：

- 程式語言
- 前端框架
- 資料庫
- CSS 方案
- 目錄結構
- 測試框架

工廠不管產品怎麼寫。工廠只管產品能不能被驗證、能不能上線、能不能被監控。

這條界線要守住。合約每多一項，技術棧的選擇就少一批，而工廠換不到任何東西。

---

## 6. 合約宣告

產品用一份合約宣告告訴工廠「我這三項長什麼樣」。

工廠讀合約宣告，不猜。這樣同一份技能檔服務得了不同技術棧，只要它們都宣告得出來。

合約宣告要宣告的東西：

1. 預覽網址從 PR 的哪裡讀
2. 重置初始資料的指令
3. 每組測試帳號的身分與登入步驟
4. 動態區域的容許清單

檔案格式與欄位名稱還沒定。等證據產生器寫出第一版，欄位需求才會準。先定需求，不先定格式。

---

## 7. 選技術棧的判準

技術棧後定。定的時候只問一句：

> 這一套最便宜地提供上面三項嗎？

三項的難度差很多：

| 要求 | 難度 | 說明 |
|---|---|---|
| 一 預覽網址 | 低 | 多數部署平台免費給 per-PR preview |
| 三 固定登入 | 低 | seed 一個測試帳號就好 |
| 二 可重現初始資料 | 高 | 要每個 preview 一個獨立且可重置的資料庫 |

所以實際上是要求二在選技術棧。要求一和要求三幾乎不構成限制。

---

## 8. 還沒定的事

1. 合約宣告的檔案格式與欄位名稱。見第 6 節。
2. 技術棧。見第 7 節。
3. 要求二的免費做法。每個 preview 一個獨立資料庫，不付費方案做不做得到。
4. 容許清單的寫法。逐像素比對的容許範圍怎麼表達。
