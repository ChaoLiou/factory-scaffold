# 工廠帳本

記錄「廠主為什麼出手，以及改了哪個零件讓下次不必出手」。

拿鉛筆是訊號，就像在監控裡看到一個錯誤 —— 它的意義是「有東西壞了」。短期還是會拿鉛筆補一下，但接著要修的是這座工廠。

## 寫入時機

每週跑一次外迴圈。它會撈訊號、提案、等廠主點頭，然後改零件並在這裡加一列。零件改動與那一列在**同一個 commit** 裡。

不要靠記性維護這個檔 —— 改工廠跟記一筆是同一件事，分開就會停。手動改工廠時也一樣，同一個 commit 帶這裡一行。

## 漏記查核

```bash
git log --oneline -- .claude/skills docs/tech-spec.md .factory CLAUDE.md CONTEXT.md | wc -l   # 修工廠的次數
grep -c '^| 20' docs/factory-log.md                                                           # 記下來的次數
```

兩個數字應該接近。差很多就是有幾次改了工廠沒留帳。

## 層的分布

```bash
grep -oE '^\| 20[0-9-]+ \| [^|]+ \|' docs/factory-log.md | awk -F'|' '{print $3}' | sort | uniq -c
```

防線分四層，強度遞減：**架構 > CI／靜態分析 > rules > skill**。前兩層違規就 CI 紅，後兩層工人會忘，只能疊加不能當唯一防線。

分布偏向後兩層，表示改的都是會被忘記的那種。

## 量測

四個指標，由監控站每輪記一列。見 `fac-monitor` 3.3。

人的時間與 token 時間要並列。優化目標不是少花錢，是換掉哪一種成本。

判準落差量的是 `SPEC.md` 的不變量準不準，不是工人做得好不好。它要連分母一起寫，例如 `1/8`。

規範長度是 skill 與脈絡的總行數。它是 token 時間的下界 —— 任務再簡單都要付。**規範變長而判準落差沒有下降，就是在付錢買噪音。**
