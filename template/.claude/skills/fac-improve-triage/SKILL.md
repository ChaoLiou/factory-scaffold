# 外迴圈 — 分辨站

這一份看「廠主事後改了什麼標籤」，並提案修改 `fac-triage`。

**自我改善不需要訓練模型。改一份 skill 並留帳就是外迴圈。**

## 0. 四條共同規則

三份 `fac-improve-*` 都守這四條。

1. **一次最多提兩條。** 改五條就分不出哪一條有效。
2. **沒有廠主點頭不准改檔案。**
3. **一次性的事丟掉。** typo、手滑、外部服務壞掉都不是工廠問題。
4. **零件改動與 `docs/factory-log.md` 那一列必須在同一個 commit 裡。**

第 4 條不要靠記性。改工廠跟留帳是同一件事，分開就會停。

## 1. 撈什麼訊號

### 1.0 動作紀錄每週都要讀

修正訊號要等人出手。**動作紀錄不用** —— 它每一輪都產生，而且它記得人沒注意到的那些失敗。

| 從動作紀錄看 | 意思 |
|---|---|
| 同一站反覆重試 | 那一站的判準寫得不清楚 |
| 為了一件小事讀了半個 repo | 脈絡沒指路 |
| 一直在同一個地方停下來回報 | 規則之間打架，或少了一條 |

兩個一起看才完整：修正訊號說「人覺得哪裡不對」，動作紀錄說「工人在哪裡卡住」。見腳手架的 `docs/factory.md` 4.3。


**修正訊號是廠主事後動手改掉的那個東西。**

人本來就會改。把改掉的動作留下來，是幾乎免費的標註資料。

| 訊號 | 在哪看 | 意思 |
|---|---|---|
| A | `fac-ready` → `fac-needs-spec` | 六條檢查表漏了一條 |
| B | `fac-needs-spec` → `fac-ready` | 檢查表太嚴，小事判成大事 |
| C | 類型標籤被改掉 | 四個類型的界線不清楚 |
| D | 貼了 `fac-ready` 的任務被關掉 | 「該不該做」那一步漏了 |
| E | `fac-needs-info` 問過的問題 | 同一種問題問三次，表示白話規格缺一整節 |

訊號 A 比訊號 B 嚴重。A 的意思是繞過了規格關卡，B 的意思是多寫了一份規格。

## 2. 怎麼判斷一條訊號值不值得提

| 條件 | 判斷 |
|---|---|
| 同一種改動出現三次以上 | 值得提 |
| 出現一次，但它繞過了關卡 | 值得提 |
| 出現一次，而且無害 | 丟掉 |
| 原因是廠主改了主意 | 丟掉。那不是工廠問題 |

**三次這個數字是門檻，不是規則。** 繞過關卡的那種一次就要提。

## 3. 提案的形狀

```
## 外迴圈提案 — 分辨站 — <日期>

### 提案 1：<一句話>

- 訊號：<A 到 E 哪一個>，出現 <N> 次
- 證據：<任務編號，列出來>
- 要改什麼：`fac-triage` 的 <哪一節>
- 改成什麼：<具體的句子。不要寫「加強」>
- 不改會怎樣：<一句話>

### 提案 2：…

<沒有第二條就不要寫>
```

**「改成什麼」要寫得出具體的句子。** 寫不出來就表示你還沒想清楚，那一條不要提。

## 4. 廠主點頭之後

### 4.1 看那份檔案是哪一層

| 要改的檔案 | 怎麼改 |
|---|---|
| `fac-triage`（共用） | **不要本地改。產出一個對腳手架的 PR** |
| 無前綴的 skill（專屬） | 直接改 |
| `SPEC.md`、`docs/tech-spec.md` | 直接改 |

`fac-*` 是共用的。本地改過，升級時雜湊對不上，升級會停下來。

**而且本地改掉的那一條，別座工廠拿不到。** 送 PR 回腳手架是跨工廠學習的唯一路徑。

### 4.2 留帳

`docs/factory-log.md` 加一列：

```
| <日期> | skill | <訊號> | <改了什麼> |
```

「層」那一欄填四層之一：架構、CI／靜態分析、rules、skill。

### 4.3 看層的分布

帳本的分布偏向後兩層的時候，停下來想一次：**這一條能不能往上推。**

一條規則能放在架構層就不要放 CI 層，能放 CI 層就不要放 rules 層。

改 skill 是最弱的那一層。它永遠有效，但它永遠依賴工人記得。

## 5. 硬規則

1. **一次最多兩條。** 那是改動的數量，不是方向 —— **刪掉一條沒有咬到東西的規則，跟加一條新規則一樣是改善。**
2. **沒點頭不准改。**
3. **一次性的事丟掉。**
4. **零件改動與帳本那一列同一個 commit。**
5. **共用檔案走 PR，不要本地改。**
6. **不要自己改這份 skill。** 它也是 `fac-*`。
7. **提案要跑重播集。** 改之前跑一次，改之後跑一次。沒有差別的那一條丟掉。見腳手架的 `docs/factory.md` 7.2。
8. **提案要回答「這一條會不會讓某個指標變好而產品沒變好」。** 四個指標都有那條路，見 `docs/factory.md` 8.2。
