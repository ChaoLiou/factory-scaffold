# 上線站

這一站觸發部署。

**它只能觸發，不能讀密鑰。** 密鑰存在部署平台，由平台注入。

## 0. 先讀

| 讀什麼 | 拿什麼 |
|---|---|
| `CONTEXT.md` 的「工廠運作」那一節 | 名詞 |
| `docs/tech-spec.md` 的「部署」那一節 | 部署怎麼觸發 |
| 這筆任務與它的 PR | 關卡過了沒 |

## 1. 邊界

| 做 | 不做 |
|---|---|
| 確認關卡都過了 | 判斷產品對不對 |
| 觸發部署 | 讀密鑰 |
| 確認部署真的上去了 | 合併 PR |
| 關掉任務 | 失敗了自己重試 |

**這一站上面沒有人**，所以它只做機械性的確認。任何需要判斷的事都在它前面發生完了。

## 2. 上線之前的五個確認

五個全部成立才觸發部署。任一個不成立就停下來回報。

| 確認 | 怎麼確認 |
|---|---|
| PR 合併了 | PR 的狀態 |
| CI 綠 | CI 的狀態。**紅的不准上** |
| 證據產出了 | 任務上有 `fac-evidence` |
| 廠主過了驗證關卡 | 廠主合併了那個 PR。合併就是他的點頭 |
| **合併晚於證據** | 比時間。合併的時間要晚於證據貼上的時間 |

### 2.1 為什麼合併就算點頭

驗證關卡的形狀是「廠主看證據，然後決定要不要合併」。

所以合併這個動作本身就是那一關的產出。**不要另外再問一次。**

多問一次會讓廠主學到「合併不算數」，然後兩個動作都變得沒有意義。

### 2.1.1 所以要比時間

合併算點頭，前提是**證據那時候已經在那裡**。

合併早於證據，表示他在沒有東西可以看的時候就合併了。那一關是空的。

**空關卡比沒有關卡更糟** —— 沒有核准章的時候下游會自己查，有一枚假的章就停止查了。所以這一條不是多禮貌的確認，它是那一關唯一的機械證據。

這一條擋不住「看了三秒就合併」。它只擋得住「根本沒有東西可以看」。

### 2.2 CI 紅不准上

資安那四項檢查裡，前兩項違規就 CI 紅：憑證被打包進前端、row level security 被關掉。

**那兩項是擋在 CI 的，不是擋在關卡的。** 所以這一站不看資安那一頁，只看 CI 的顏色。

繞過 CI 上線，等於把四層防線裡最強的那一層關掉。

## 3. 這一站怎麼跑

### 3.1 讀部署怎麼觸發

照 `docs/tech-spec.md` 的「部署」那一節。

**那一節沒寫就停下來。** 不要猜，也不要去找部署設定檔自己推。

部署怎麼觸發寫在 `docs/tech-spec.md` 的「部署」那一節。那一節是空的就是建廠產線第 3 站沒接完 —— 停下來回報，不要自己猜一個指令。

### 3.2 觸發

觸發，然後等它完成。

**不要讀密鑰，也不要把密鑰帶進指令。** 你看得到密鑰這件事本身就是違規，不管你有沒有用它。

生產密鑰不進工人的執行層。那是五條架構規則的第五條。

### 3.3 確認真的上去了

部署平台回報成功不等於產品好了。

| 確認 | 怎麼確認 |
|---|---|
| 生產環境回應得了 | 打一次首頁或 health endpoint |
| 版本對 | 上去的是這個 commit |

兩個都過，關掉任務。

**沒有 `fac-shipped` 標籤。** 關掉任務本身就是那個狀態。

### 3.4 失敗了停下來

| 情況 | 怎麼辦 |
|---|---|
| 觸發失敗 | 停。回報 |
| 部署過程失敗 | 停。回報 |
| 上去了但確認不過 | 停。回報，並寫明是哪一項確認不過 |

**不要重試三次。** 不要自己回滾。

回滾是一個會改變生產環境的決定，而這一站上面沒有人。失敗的部署留在那裡，比一個自動回滾然後沒人知道的狀態安全。

## 4. 硬規則

1. **五個確認全部成立才觸發。**
2. **CI 紅不准上。**
3. **不要讀密鑰。** 看得到就是違規。
4. **不要合併 PR。** 合併是廠主在驗證關卡做的。
5. **部署怎麼觸發沒寫就停。** 不要猜。
6. **失敗不要重試，不要回滾。** 停下來回報。
7. **一次上一筆任務。** 兩筆一起上，壞了分不出是哪一筆。

## 5. 修正訊號

| 廠主做了什麼 | 意思 |
|---|---|
| 自己手動部署 | 這一站的觸發路徑斷了，或者五個確認太嚴 |
| 自己回滾 | 上線後才發現的問題。那是驗證站或審查站漏的 |
| 改掉 `tech-spec.md` 的「部署」那一節 | 那一節寫得你讀不懂 |

**上線之後才發現的問題，訊號不屬於這一站。** 它屬於驗證站或審查站 —— 它們本來該在上線之前看到。

這一站的訊號只有「觸發這件事順不順」。
